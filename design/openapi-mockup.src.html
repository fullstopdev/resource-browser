An API reference you can scan in seconds

The current OpenAPI pages, what slows them down, and a working example of the proposed workbench built on real 26.8.2 API data. The built version is shown further down.

Before

What the current pages get wrong

  1. Five boxes before the first endpoint. Page card, "Browse specs", API header, tab bar and list panel take about 400 px.
  2. Endpoints are hidden. Tags start collapsed, so no method or path is visible until you open each one.
  3. The detail is a modal. Opening an endpoint covers the list, so comparing two endpoints means closing and reopening.
  4. Two release pickers and two half-width blue tabs compete with the content.
  5. Compare APIs starts with a stepper and two big boxes, and shows "56 Shared · 0 Unchanged · 0 shown" when nothing changed.

After

Proposed design, working example

Pick an API, filter by method, click an endpoint to open it in the side panel, switch to Compare APIs, and flip device and theme. Endpoints, parameters and the comparison counts are real.

    Built

    The redesign running on the real site

    Screenshots from the production build after the change, 1440 × 900 and a 390 px phone.

    What changes

    Implementation outline

    API Explorer

    • One head row: breadcrumb, API title, version, OAS, path count and auth chips, and a Paths / Schema graph switch.
    • Sidebar: searchable API picker (core first, then apps), a filter, method toggles and the tag list.
    • Endpoints listed by tag and expanded: method badge, path with {params} highlighted, summary.
    • Endpoint detail in a side panel: copy path and curl, parameters table, request body, responses by status, examples, show in schema graph. Full screen on phones.
    • Keyboard: arrows move between endpoints, Enter opens, Escape closes, / focuses the filter.

    Compare APIs

    • One compare bar: source → target, swap, compare, share link. No stepper.
    • Summary tiles for APIs added, removed, changed and operations added and removed.
    • Results by API with diff-style lines: + added, − removed, method badges, mono paths.
    • A clear empty state when two releases have no API changes.
    • Everything uses the homepage's tokens, so the two themes match the rest of the site.
