Design proposal · homepage and top menu

A cleaner front door for the EDA Resource Browser

The current homepage and menu, with what holds them back, then a working example of the proposed design built on real 26.8.2 data. The built version is shown further down.

Before

What the current design gets wrong

  1. Two-row menu with 10 flat links. Tiny group labels (CRD, API, HELP) do the grouping, and "Comparison" appears twice.
  2. The release is shown three times (release card, Quick actions, the selected button) but can't be changed from other pages' menu.
  3. No statement of what the site is. "EDA CRD Schema Explorer" sits in a box with no description, counts or next step.
  4. Quick actions repeat the menu as a tall list, leaving a large empty area under the release picker.
  5. Search lives only on the homepage. Other pages have no way to jump to a CRD.
  6. Generic name and weak brand. "Resource Browser" doesn't say Nokia EDA, and the logo sits at 28 px with no product line.

After

Proposed design, working example

Open the menus, switch the release, type in the search, and flip the device and theme. Counts, versions and schema fields are real 26.8.2 data. Fonts here stand in for the site's Nokia Pure fonts, which stay.

Phone: logo, release, theme and a menu button that opens the same three groups as a sheet.

Homepage: says what it is, then gets out of the way

  • A heading and one line with real counts (CRDs, API groups, releases) from the manifest.
  • Search as the main action, with popular kinds as shortcuts.
  • A live schema example of one CRD, so the first screen shows the product.
  • Releases as two version trains (v25, v26), with the latest marked and the latest change summary.
  • Eight tool tiles with one fact each, replacing the Quick actions list and the duplicate release card.

Kept: Nokia Pure fonts, the logo, light and dark themes, existing routes and URLs. The accessibility scan stays in CI.
